# AI 在黑盒导入任务里的典型失误与对策

> 全部是一次真实战役里 AI 真犯过、被用户或复核抓出来的错。按「开工 → 分析 → 生成 → 自检 → 交付 → 汇报」排序。

## 开工

| 失误 | 根因 | 对策 |
|---|---|---|
| 合并别人给的 Excel 时，把被筛选隐藏的十一万多行一起并了进来，没告诉用户 | 只读单元格的值，不看文件状态 | 开工先体检：筛选、隐藏行列、公式、外部链接、表头行、示例行、合并单元格；「全部行还是可见行」列为必问项 |
| 连着两轮失败，才去找成功样本 | 只在给定文件里闭门推理 | 开工第一问：导入记录全页、历史成功文件、同事的版本、平台管理员的口径 |
| 按字面删列，把区分同名表的那一列（Schema）也删了，造出几百组假重复 | 删之前没做键分析 | 删列前先问：这列是不是某个自然键的一部分？是的话提醒用户或留备份 |

## 分析

| 失误 | 根因 | 对策 |
|---|---|---|
| **回音室**：AI 三次主动提议「数据库名称改填 Schema」，还说是「主要原因」；用户随后问「不是需要填 schema 吗？」，AI 把这句当成确认，改了——平台其实要的是实例名，此后四次上传全部 0 成功 | 把本地模拟自洽当证实；让表头括注压过释义行和主键说明；自己的推断经用户转述回来被当成外部证据 | 用户的疑问句不等于规则；先分清这话来自平台证据、用户领域知识，还是你之前说的；分不清就问「这是平台要求，还是看表头推断的？」 |
| 看报错列号点名了一个非必填列，就去填它（归属域），又白传一次 | 把平台 UI 的列号当可靠信号 | 列号和报错文案也只是线索，要和成功样本交叉验证 |
| 同一个差额数字出现两次，隔了近一小时才对上 | 没把平台回报的数字当成可检验的约束 | 总数 / 成功 / 失败 / 错误条数逐个和候选口径的计数比；任何差额都必须解释 |
| 去重漏掉只差换行符、前导空格的行 | 按原值精确比较 | 比较前规整：去首尾空白，处理内嵌换行、全角空格、不间断空格、零宽字符；大小写按目标系统口径 |
| 把网上搜来的推测（「可能是某厂商产品」）当成印证 | 没看过原件的环节当成了事实 | 没看过的只能写「推断」；网搜推测不作印证 |

## 生成

| 失误 | 根因 | 对策 |
|---|---|---|
| 清理规则过猛：「去掉汉字旁的空格」把「检查状态 0-待校验 1-已通过」粘成一串 | 规则按直觉写，没先在真实样本上测 | 清理规则先拿真实样例写反例测试；改动量异常（一次四万多格）就停下查——这次是这么抓住的 |
| 编辑失败后跑的测试其实是旧代码 | 没确认改动生效就测 | 编辑失败就回读或整文件重写，再测 |
| 把「识别重复」扩成「按多数写法统一」，替用户选了值 | 把「可以直接修改」理解得过宽 | 识别和修改分开交付；有冲突只列出，除非用户明确放权 |
| 用户明说「我也无从判断，你觉得哪个对就留哪个」，AI 仍把一批冲突交还用户 | 回避拍板 | 用户放权时：默认决策＋理由＋可回滚记录 |
| 输出文件和源文件放一起，两处出现同名不同内容的文件 | 没有版本意识 | 输出放独立目录，文件名带版本和日期；每次交付说一句「这版和上版差在哪」 |

## 自检与交付

| 失误 | 根因 | 对策 |
|---|---|---|
| 自检宣称「完全一致」，实际有二十多万格从空串变成了真空白 | 用同一个库读写和比对，盲点相同；做了等价折叠却没写明 | 换一条解析路径复核，并做阳性对照；做了折叠就写在宣称里 |
| 「按模板规则 50 项 36 项通过」就交付，平台 0 成功 | 验收基准是自己对模板的理解，不是目标系统 | 没有平台真实反馈，不许写「可以上传」；结论带「范围 / 未覆盖」 |
| 探针和全量候选同批交付，还附了句「如果这几行能过就直接传全量」，用户跳过探针直接传了全量 | 给了捷径就会被走捷径 | 探针单独交付并设闸；全量只在探针结论之后生成 |
| 用户说「先不要再做修改了」，AI 整包撤回，把正确的需求（系统名前缀）也弄丢了，后来它恰好是平台规则之一 | 没有需求台账，撤回不逐项确认 | 维护需求台账（做了 / 撤了 / 挂起）；撤回逐项确认；每版交付对照台账逐条说明 |
| 把一个方向记成「已修」并写下教训「带括注的列名以括注为准」，后来被平台实测推翻 | 教训在真实系统验证之前就入了账 | 涉及外部系统的修复记为「待实测」，拿到平台结果再定性；被推翻的教训回去改原条目 |

## 汇报

| 失误 | 根因 | 对策 |
|---|---|---|
| 给领导的汇报稿压缩时，把「成功数待填【 】」压成了确定的数字和「已全部导入」 | 追求简短，把限定词一起删了 | 对外文字只写用户给过或平台证实的数；没证实的保留占位或写成条件句 |
| 上下文压缩后两次用英文回复中文用户 | 常驻偏好没随压缩保留 | 压缩或切换模式后重申语言与格式偏好 |

## 做对了、值得保留的

- 不覆盖原件，另存新文件；写前检查文件是否被 WPS/Excel 占用。
- 每处取舍落进修改说明，能查到原值。
- 用两种读法（pandas 与 openpyxl）独立复核。
- 派复核时明确要求「不复用生成脚本、计数给独立基线」。
- 每个结论后面跟一行诚实的「范围：…；未覆盖：…」。
